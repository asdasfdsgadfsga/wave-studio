# РУКОВОДСТВО ДЛЯ AI-АГЕНТА ПО ПРОЕКТУ WAVE STUDIO

Этот документ создан как единая инструкция для любого AI-ассистента (Claude, ChatGPT, Cursor, Gemini, Copilot и др.), который работает с данным репозиторием. Здесь описаны правила работы с Git/GitHub, архитектура сайта, стек технологий и критические ограничения.

---

## 1. БАЗОВАЯ ИНФОРМАЦИЯ О ПРОЕКТЕ

* **Название проекта:** Wave Studio (WaveMusic).
* **Суть проекта:** Современный веб-сайт студии звукозаписи с интегрированной бесплатной клиентской Web DAW (виртуальной студией звукозаписи прямо в браузере) и встроенным AI-саунд-продюсером с двумя режимами общения («Pro» и «Вася по понятиям»).
* **Основной Git-репозиторий:** `https://github.com/asdasfdsgadfsga/wave-studio.git`
* **Рабочая ветка:** `main` (всегда пушим строго в `main`).
* **Хостинг и продакшн-домен:** Cloudflare Pages — `https://wavemusic.pages.dev` (CI/CD настроен автоматически от GitHub).

---

## 2. ГАЙД ПО GIT И GITHUB ДЛЯ НЕЙРОСЕТИ

Каждый раз, когда вносятся изменения в код, следуй строгому алгоритму работы с Git:

### Шаг 1. Проверить текущий статус и диффы
Всегда смотри, какие файлы были затронуты:
```bash
git status
git diff
```

### Шаг 2. Добавить только нужные файлы в индекс
Добавляй файлы точечно (или `git add .`, если все измененные файлы относятся к задаче):
```bash
git add index.html widget/chat-widget.js functions/api/chat.js
```

### Шаг 3. Сделать понятный коммит (Conventional Commits)
Пиши лаконичные и осмысленные сообщения коммитов:
```bash
git commit -m "feat(ui): add new vocal preset selector in web daw"
# или
git commit -m "fix(chat): correct safe-area padding for mobile viewport"
```

### Шаг 4. Отправить изменения на GitHub
```bash
git push origin main
```

### Шаг 5. Как работает автодеплой (CI/CD)
1. Как только коммит отправлен в ветку `main`, Cloudflare Pages автоматически запускает сборку и обновляет сайт за 20–40 секунд.
2. Проверить готовность обновления можно через консоль:
```bash
curl -I https://wavemusic.pages.dev
# Либо запросить версию виджета:
curl -s https://wavemusic.pages.dev/widget/chat-widget.js
```

### ⚠️ КРИТИЧЕСКИЕ ПРАВИЛА И ЗАПРЕТЫ В GIT (ТАБУ!):
1. **НИКОГДА НЕ ПУШЬ API-КЛЮЧИ В ОТКРЫТОМ ВИДЕ!**
   * GitHub Push Protection моментально заблокирует push при обнаружении ключей вида `gsk_...`, `AIzaSy...`, `AQ....` с ошибкой `GH013: Repository rule violations found`.
   * Для локального сервера ключи хранятся в `server/.env` (этот файл находится в `.gitignore` и не попадает в репозиторий).
   * Если в коде функций (`functions/api/chat.js`) требуется дефолтный резервный ключ, его **обязательно** разбивают на части в массив строк (например: `['AQ.', 'Ab8RN6J', ...].join('')`) либо берут из переменных окружения Cloudflare (`env.GEMINI_API_KEY`, `env.OPENAI_API_KEY`).
2. **НИКОГДА НЕ ИЗМЕНЯЙ БИНАРНЫЕ ФАЙЛЫ ПРЕЗЕНТАЦИЙ!**
   * Файлы `Wave_Studio_Presentation.pptx` и `Wave_Studio_Presentation.pdf` нельзя открывать текстовыми редакторами или перетирать.
3. **НЕ ТРОГАЙ АРХИВНЫЕ ПАПКИ:**
   * Папки `archive/` и `!ДОКИ/` трогать без явного указания пользователя не нужно.

## 3. АРХИТЕКТУРА И СТРУКТУРА ПРОЕКТА

```
wave/
├── index.html             # Главный лендинг Wave Studio
├── app.html               # Полноценная клиентская Web DAW (браузерная студия)
├── style.css              # Основные стили лендинга (тёмная неоновая тема)
├── script.js              # Интерактив лендинга, плеер, отзывы, модалки
├── widget/                # Виджет AI-консультанта (работает через Shadow DOM)
│   ├── chat-widget.js     # Логика виджета, разметка, вызовы API
│   └── widget.css         # Стили виджета (градиенты, анимации, мобильный адаптив)
├── functions/             # Серверные функции Cloudflare Pages
│   └── api/
│       └── chat.js        # Бессерверный роут /api/chat (Gemini + Groq fallback)
├── server/                # Локальный Node.js Express сервер (порт 3005)
│   ├── index.js           # Сервер для локального тестирования чат-бота
│   ├── system_prompt.txt  # Системный промпт: режим Pro
│   ├── street_prompt.txt  # Системный промпт: режим Вася по понятиям
│   └── .env               # Локальные переменные окружения и ключи
├── booking.js             # Форма записи через /api/booking, без фиктивного успеха
├── admin.html / admin.js  # Серверная CRM: сессии, заявки, расписание, цены
├── lib/booking/           # Общая логика API и локальный SQLite-адаптер
├── migrations/            # SQL-схема Cloudflare D1
├── backend/               # Локальный API и превью сайта, Node 24+ (порт 3000)
└── images/                # Статические изображения, фото артистов, логотипы
```

### Описание ключевых модулей:

1. **`index.html` (Лендинг):**
   * Презентует оффлайн-студию Wave Studio (услуги записи, сведение, мастеринг, микрофон Neumann U87, мониторы Genelec).
   * Ссылается на веб-DAW через кнопку «В DAW» (`app.html`).
   * В конце `<body>` подключает виджет: `<script src="widget/chat-widget.js" data-api="/api/chat"></script>`.

2. **`app.html` (Онлайн Web DAW):**
   * Работает **на 100% на клиенте** через Web Audio API.
   * Не требует регистрации, баз данных или сторонних серверов.
   * Функционал: 8-дорожечная драм-машина, 160+ встроенных сэмплов, виртуальные синты, пианоролл, спектроанализатор, экспорт трека в WAV/MP3.

3. **`widget/chat-widget.js` (AI-чат):**
   * Изолирован внутри **Shadow DOM**, чтобы стили страницы и виджета не конфликтовали.
   * Плавающая кнопка расположена строго в **нижнем левом углу** (`bottom: 24px; left: 24px`).
   * Поддерживает мобильные экраны: использует `100dvh`, обработчик `visualViewport` (при выезде клавиатуры на iOS/Android чат не обрезается), и `safe-area-inset`.
   * Автоматически определяет окружение:
     * На `localhost` отправляет запросы на `http://localhost:3005/api/chat`.
     * На продакшене отправляет запросы на относительный путь `/api/chat`.

4. **`functions/api/chat.js` (Продакшн бэкенд чата):**
   * Работает прямо на Cloudflare Pages без выделенного сервера.
   * **Двухуровневая отказоустойчивая система:**
     1. **Основной провайдер:** Google Gemini API (`gemini-3.1-flash-lite`, fallback `gemini-3.5-flash`). Работает молниеносно, без лимитов 429.
     2. **Резервный провайдер:** Groq API (`qwen/qwen3.8-27b`, fallback `openai/gpt-oss-20b`), если Google временно недоступен.
   * Контролирует лимит токенов ответа (`maxOutputTokens: 280`), чтобы ответы были быстрыми и емкими.

5. **Бронирование (`booking.js`, `functions/api/booking/[[path]].js`):**
   * Форма обращается к `/api/booking` на том же домене. Успех показывается только после сохранения в базе. Никогда не возвращать прежний фиктивный успех или хранение новых заявок только в localStorage.
   * Продакшн: Cloudflare D1 binding `BOOKING_DB` и Secret `BOOKING_ADMIN_PASSWORD` (от 16 символов). До подключения форма предлагает связаться со студией.
   * Локально: `node backend/server.js`, сайт `http://127.0.0.1:3000`, переменные в игнорируемом `.dev.vars`, база `.local/booking.sqlite`.
   * Админка использует серверные HttpOnly-сессии. Клиентских паролей и localStorage для авторизации нет.
   * Telegram/Resend подключаются только через секреты окружения; по умолчанию выключены. Подробности: `docs/booking-backend.md`. Проверки: `node --test tests/booking.test.mjs`.

## 4. ПРАВИЛА И СТРОГИЕ СТАНДАРТЫ ДЛЯ AI-ЧАТА

В проекте есть две личности AI-консультанта:
1. **Режим Pro («WAVE AI PRODUCER»):** Компетентный студийный звукорежиссёр и саунд-продюсер Wave Studio. Доброжелательный тон, профессиональные термины.
2. **Режим Street («ВАСЯ ПО ПОНЯТИЯМ»):** Старший звукарь-самородок с района. Базарит по понятиям, использует аутентичный русский мат открытым текстом, коронное «вась», знает историю пацанского рэпа (Баста, Каспийский Груз, АК-47, CENTR, Кровосток). Слово «ё-маё» категорически запрещено.

### 🚫 ТАБУ ФОРМАТИРОВАНИЯ ТЕКСТА БОТА (КРИТИЧНО!):
Нейросеть в ответах клиенту ОБЯЗАНА соблюдать следующие правила (они также прописаны в промптах и функции очистки `cleanPlainReply`):
* ❌ **НИКАКИХ таблиц Markdown** (`| --- |`) — они ломают мобильный интерфейс чата.
* ❌ **НИКАКИХ звёздочек `**`** (жирный шрифт и курсив). Текст должен быть чистым.
* ❌ **НИКАКИХ решёток заголовков (`#`, `##`, `###`)** и разделительных линий (`---`).
* ❌ **НИКАКИХ дефисов в начале строк** для списков у Васи.
* ⚡ **ЖЁСТКОЕ ТРЕБОВАНИЕ КРАТКОСТИ:** Ответ должен быть 1–2 небольших абзаца (2–4 предложения). Без длинных простыней текста, чтобы пользователь на смартфоне сразу видел суть без необходимости бесконечного скролла.

## 5. ЛОКАЛЬНАЯ РАЗРАБОТКА И ТЕСТИРОВАНИЕ

* **Запуск локального сервера чата:**
  ```powershell
  cd server
  node index.js
  ```
  Сервер стартует на `http://localhost:3005`.
  Проверка статуса: `http://localhost:3005/api/health`.

* **Запуск самого сайта:**
  Достаточно открыть `index.html` через VS Code Live Server или любой локальный HTTP-сервер на порту 5500 / 8080. Виджет автоматически определит `localhost` и будет слать запросы в локальный Node.js на порту 3005.

* **Тест API локально через консоль:**
  ```bash
  node -e "fetch('http://localhost:3005/api/chat',{method:'POST',headers:{'Content-Type':'application/json'},body:JSON.stringify({message:'Привет',mode:'pro'})}).then(r=>r.json()).then(console.log)"
  ```

* **Тест API на продакшене (Cloudflare Pages):**
  ```bash
  node -e "fetch('https://wavemusic.pages.dev/api/chat',{method:'POST',headers:{'Content-Type':'application/json'},body:JSON.stringify({message:'Привет',mode:'street'})}).then(r=>r.json()).then(console.log)"
  ```
