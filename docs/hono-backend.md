# Единый бэкенд WaveMusic на Hono

Рабочее API реализовано на JavaScript с фреймворком Hono. Cloudflare Pages
и локальный Node.js запускают одно приложение `lib/api/app.mjs`.
Сайт, клиентская DAW и существующая D1-база не требуют переноса.

## Структура

- `lib/api/app.mjs` — маршруты Hono, общие заголовки, валидация чата,
  ограничения размера запроса и обработка ошибок.
- `lib/chat/api.mjs` — запросы к Gemini, резервный OpenAI-совместимый API,
  таймауты и очистка ответа с сохранением навигации виджета.
- `lib/booking/api.mjs` — правила записи, сессии администратора, лимиты,
  уведомления и атомарные операции базы. Логика сохранена при переносе.
- `functions/api/[[path]].js` — тонкий Fetch-адаптер Pages.
- `backend/server.js` — локальный запуск того же API и безопасная выдача
  файлов сайта, включая Range-запросы для перемотки.
- `functions/audio/[[path]].js` — прежняя поддержка Range для двух WAV
  в Pages. Она остаётся отдельной функцией статических ресурсов.

## Маршруты

`GET /api/health` сообщает о работе приложения Hono.
`POST /api/chat` и `OPTIONS /api/chat` сохраняют адрес чата.
`/api/booking/*` сохраняет все публичные и административные маршруты.
Неизвестные маршруты API отвечают JSON с кодом 404.

Для чата проверяются JSON, режим, непустое сообщение до 4 000 символов
и массив истории. Тело ограничено 64 КиБ; используется не более 10 сообщений
истории, только роли user/assistant, по 4 000 символов. Проверки бронирования,
его лимит 8 КиБ, same-origin и закрытые cookie-сессии не ослабляются.
Публичный CORS разрешён только для виджета чата, не для админки.

## Локальный запуск

Требуется Node.js 24+. Из корня проекта:

```sh
npm ci
npm start
```

Сайт и всё API доступны на `http://127.0.0.1:3000`.
`BOOKING_PORT` меняет порт. Виджет использует `/api/chat` на том же сервере.
Локальная база `.local/booking.sqlite` и секреты не включаются в Git.
Сервер читает `.dev.vars`, затем `server/.env`; существующие переменные
процесса имеют приоритет. Пароль `BOOKING_ADMIN_PASSWORD` должен содержать
не менее 16 символов. Настройка бронирования описана в `booking-backend.md`.

`server/index.js` оставлен как прежний отдельный Express-сервер для экспериментов.
Для обычной разработки запускать его на 3005 больше не нужно.
При внешнем подключении виджета абсолютный адрес можно задать через `data-api`.

## Секреты чата

В production ключи задаются только в секретах существующего проекта Pages:
`GEMINI_API_KEY` для Gemini и/или `OPENAI_API_KEY` для резервного провайдера.
`OPENAI_BASE_URL` и `OPENAI_MODEL` необязательны; по умолчанию используется
Groq. При отсутствии ключей чат честно возвращает 503. Резервных ключей
в исходном коде больше нет. Тела ошибок провайдеров не уходят клиенту.
Прежде чем публиковать миграцию, необходимо настроить хотя бы один ключ.

## Проверки и публикация

```sh
npm test
npx wrangler pages functions build functions --outdir .booking-dist
```

Тесты бронирования проходят через Hono, включая пересечения, повторы,
смену статусов, переносы, сессии и ограничения. Отдельно проверяются
границы HTTP API, чат и Range-запросы. `package-lock.json` фиксирует
зависимости; корневая зависимость runtime — Hono.

В настройках сборки существующего проекта Pages задано `npm ci && npm run build`:
проект раньше пропускал установку зависимостей при пустой команде сборки.
После push в main устанавливается Hono, проверяются промпты и собираются функции.
Настройки D1, схема и данные не меняются.
Проверить после деплоя: health, config, чат, вход администратора и перемотку.
