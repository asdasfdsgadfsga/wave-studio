# Бронирование WaveMusic

## Что работает

Единое приложение Hono обслуживает Cloudflare Pages и локальный Node.js. В продакшене данные хранятся в Cloudflare D1, локально — в `.local/booking.sqlite` (не попадает в Git). Общая архитектура описана в `hono-backend.md`.

- Форма получает свободные часы с сервера и показывает успех только после сохранения заявки.
- Расписание общее для студии и всех услуг, круглосуточное, по Хабаровску (`Asia/Vladivostok`, UTC+10). Длительность сессии 1–8 целых часов, начало минимум через 2 часа, горизонт 90 дней.
- Новая заявка получает статус `pending` и резерв на 24 часа. Администратор подтверждает её после согласования деталей/предоплаты. До этого она не является подтверждённой записью.
- `booking_slots.starts_at` — уникальный ключ часа. Создание/перенос и все часы сессии записываются одной атомарной транзакцией D1 `batch`. Пересечения, включая полночь, невозможны. При конфликте возвращается 409 без частичных данных.
- Повтор отправки с тем же `requestId` возвращает прежнюю заявку. Одновременные изменения администраторов защищены номером `version`.
- Истёкшие резервы освобождаются при чтении расписания/журнала и перед созданием заявки; отдельный cron не нужен.
- Админка `/admin.html`: вход, статусы, перенос, заметки, фильтры по дате/статусу, страницы по 100 записей, CSV текущей страницы, общие цены сайта.
- Статусы: `pending → confirmed/cancelled`, `confirmed → completed/cancelled`. Завершение разрешено после конца сессии. Истёкшие/отменённые записи не восстанавливаются: создаётся новая заявка.
- Старые `localStorage.waveBookings` автоматически не импортируются. На прежнем устройстве админка позволяет скачать их JSON-архив; новые заявки доступны с любого устройства через сервер.

## Локальный запуск

Требуется Node.js 24+. Перед первым запуском выполнить `npm ci` из корня проекта для установки Hono.

1. Скопировать `booking.env.example` в `.dev.vars` в корне проекта.
2. Задать уникальный случайный `BOOKING_ADMIN_PASSWORD` длиной от 16 символов. Не использовать пароль из тестов и не коммитить файл.
3. Запустить `node backend/server.js` из корня проекта.
4. Открыть `http://127.0.0.1:3000/#booking` и `http://127.0.0.1:3000/admin.html`.

`BOOKING_PORT` меняет порт. Сервер слушает только loopback. Старые `/api/book`, `/api/template` заменены; учётные данные SMTP в коде отсутствуют. Чат и бронирование теперь работают через Hono на одном сервере; отдельный процесс на 3005 не нужен. Статический `serve.js` не обслуживает API.

## Включение в Cloudflare Pages

Потребуется доступ к существующему проекту `wavestudiopro` (домен `wavemusic.pages.dev`). Платная подписка в коде не подключается. Не публиковать ключи ни целиком, ни разбитыми на строки.

1. Создать D1 базу `wave-bookings` в **Workers & Pages → D1**.
2. Выполнить `migrations/0001_bookings.sql` в консоли этой базы. SQL идемпотентен: существующие таблицы/заявки не удаляет.
3. В **Pages → wavestudiopro → Settings → Bindings** добавить D1 binding **`BOOKING_DB`**, выбрав эту базу. Настроить Production; для Preview использовать отдельную тестовую базу.
4. В **Settings → Variables and Secrets** добавить **`BOOKING_ADMIN_PASSWORD`** как Secret (16+ случайных символов). В админке используется именно этот пароль. Не задавать его через публичные переменные сборки или JS.
5. Передеплоить последний Production deployment. Изменения bindings/secrets применяются к новому деплою.
6. Проверить `/api/booking/config`: `ready: true`. Затем `/admin.html`: без входа API журнала отвечает 401, после входа появляется журнал. Проверочную запись создавать с собственными тестовыми контактами; завершить проверку отменой через админку.

Вариант через официальный CLI после `npx wrangler login`:

```powershell
npx wrangler d1 create wave-bookings
npx wrangler d1 execute wave-bookings --remote --file migrations/0001_bookings.sql
npx wrangler pages secret put BOOKING_ADMIN_PASSWORD --project-name wavestudiopro
```

Привязку `BOOKING_DB` к существующему Pages проекту всё равно нужно добавить. У проекта с автоматическим Git-деплоем настройки Pages сохраняют текущий способ публикации; фиктивный `database_id` в репозиторий не добавлен.

Пока база и пароль не подключены, `config` возвращает `ready: false`, запись отвечает 503. Форма честно предлагает связаться со студией и не создаёт фиктивных подтверждений.

## Уведомления (подготовлены, выключены по умолчанию)

Все переменные ниже добавляются **как Secrets в Cloudflare Pages**, затем выполняется новый деплой. Локально — только в `.dev.vars`.

**Telegram администратору:** `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`. Создать бота через BotFather, добавить его в нужный чат и получить ID чата. Уведомления: новая заявка, подтверждение, отмена, перенос, завершение. Текст без HTML/Markdown, содержит контакты клиента; выбирать приватный чат студии.

**Письма клиенту через Resend:** `RESEND_API_KEY`, `BOOKING_EMAIL_FROM` (например, имя студии и адрес на подтверждённом домене). Сначала подтвердить домен отправителя в Resend. Письма отправляются при подтверждении, отмене и переносе подтверждённой записи; предварительный резерв не называется подтверждённой записью. Idempotency-Key защищает от повторного письма при одинаковой версии заявки.

Админка показывает, какие подключения настроены. Доставка best effort с таймаутом 8 секунд, без очереди повторов. Сбой уведомления не удаляет сохранённую заявку; при ошибке доставки после действия администратора показывается сообщение. Для новой заявки Telegram запускается через `waitUntil`; журнал остаётся источником актуальных заявок.

## API и доступ

Публичные маршруты:

- `GET /api/booking/config` — готовность, часовой пояс, услуги и цены, без секретов.
- `GET /api/booking/slots?day=YYYY-MM-DD&duration=2` — свободное время, без контактов клиентов.
- `POST /api/booking/bookings` — `{requestId,name,email,phone,service,startsAt,duration,consent:true,website:""}`. `startsAt` — ISO UTC из списка слотов; услуги `vocal`, `mix`, `beat`. Ответ содержит только ID, статус, время и срок резерва.

Администратор:

- `POST /api/booking/admin/login` — `{password}`.
- `GET /api/booking/admin/session`, `POST /api/booking/admin/logout`.
- `GET /api/booking/admin/bookings?status=&day=&offset=0`.
- `PATCH /api/booking/admin/bookings/:id` — `{version,status?,note?,startsAt?,duration?}`.
- `GET/PUT /api/booking/admin/settings` — цены `{vocal,mix,beat}`.

Сессии на 8 часов: случайный токен в HttpOnly/SameSite=Strict/Secure cookie; в базе только SHA-256 токена. Выход удаляет сессию. Запросы с изменением данных проверяют Origin. Ответы API имеют `Cache-Control: no-store`. Лимиты попыток хранятся в D1: вход 5/15 минут/IP, заявки 5/час/IP и 5/сутки/email, расписание 120/минуту/IP. IP сохраняется только как хеш с секретом. Тело JSON ограничено 8 КБ, все SQL-параметры связаны, пользовательский текст в админке выводится через textContent. CSV защищён от формул.

Смена `BOOKING_ADMIN_PASSWORD` сама по себе не удаляет действующие сессии. При отзыве доступа выполнить `DELETE FROM booking_sessions;` в D1 и задать новый секрет. Не публиковать выгрузки базы и CSV: они содержат контакты. При необходимости удаления контактных данных по обращению клиента удалить соответствующие `booking_events`, затем `bookings` по ID в одной транзакции; связанные `booking_slots` удаляются каскадно. Штатный интерфейс вместо удаления использует отмену для сохранения истории.

## Проверки и резервная копия

```powershell
node --test tests/booking.test.mjs
node --check booking.js
node --check admin.js
npx wrangler pages functions build functions --outdir .booking-dist
```

Тесты используют настоящую изолированную SQLite базу в памяти: конкурирующие брони, откат конфликтного переноса, идемпотентность, переход через полночь, истечение резерва, сессии, Origin, ограничения запросов, конкурентные изменения и цены. Продакшн база в них не используется.

Резервные копии — D1 Time Travel или `npx wrangler d1 export wave-bookings --remote --output <приватный-путь>`. Локальная база — файл `.local/booking.sqlite`; копировать при остановленном сервере. Миграции хранить в Git, выгрузки и секреты — вне репозитория. Подробнее: [D1](https://developers.cloudflare.com/d1/), [Pages bindings](https://developers.cloudflare.com/pages/functions/bindings/).
